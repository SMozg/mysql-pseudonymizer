На вход — работающая база MySQL, на выход — она же: та же схема, столько же строк, те же связи,
но без персональных данных. Замены осмысленные, а не `xxxxx`, и обратимые по словарю.

Автор — Сергей Москалёв, [@SergeiMoskalevV](https://t.me/SergeiMoskalevV).

## Как это выглядит на строках

Демо-база Sakila, выхлоп прогона. **Жирным** — что изменилось, остальное — байт в байт.

| строка | ДО | ПОСЛЕ |
|---|---|---|
| `customer` 1 | **`MARY`** · **`SMITH`** · **`MARY.SMITH@sakilacustomer.org`** · addr 5 · 2006-02-14 | **`OLIVIA`** · **`STEWART`** · **`OLIVIA.STEWART@sakilacustomer.org`** · addr 5 · 2006-02-14 |
| `staff` 1 | **`Mike`** · **`Hillyer`** · пароль **`8cb2237d06…`** · фото | **`MYRON`** · **`Hillman`** · пароль и фото — **`заглушки`** |
| `address` 1 | **`47 MySakila Drive`** · `NULL` · **`Alberta`** · `''` · `''` · city 300 | **`5455 Fuve Drive`** · `NULL` · **`Sunote Valley`** · `''` · `''` · city 300 |

`city_id`, флаги и даты не сдвинуты, `NULL` не становится значением, пустое остаётся пустым,
`email` пересобран из нового имени; `film.title` — не ПД, не тронут.

**Города — модель**: замена обязана быть настоящим городом той же страны:

| ДО | ПОСЛЕ | страна |
|---|---|---|
| `A Coruña (La Coruña)` | `Madrid` | Испания |
| `Balikesir` | `Diyarbakır` | Турция |
| `London` (city 312) | `Glasgow` | Великобритания |
| `London` (city 313) | `Calgary` | Канада |

Два `London` — одно название в двух странах — разведены на разные замены, каждая в свою
страну. Фамилии так же: `JOHNSON → RICHARDSON`, `WILLIAMS → REYNOLDS`.

**Три стратегии замены; поставщик выбирается по классу данных** — строка конфигурации
(`providers` в `config/config.yaml`), не предел инструмента:

| класс данных | поставщик | пример живого прогона | сеть | цена | повтор без словаря |
|---|---|---|---|---|---|
| имя · фамилия · город | **языковая модель** | `MIKE → MYRON` · `SMITH → STEWART` · `Sasebo → Osaka` | нужна | токены | нет |
| район · адрес | **генератор** | `Alberta → Sunote Valley` · `47 MySakila Drive → 5455 Fuve Drive` | не нужна | 0 | да, по seed |
| индекс · телефон · координата | **формат** | `35200 → 71543` · `28303384290 → 90382096363` | не нужна | 0 | да, по seed |

Модель стоит денег, задержки и отправки данных наружу. Там, где нужна узнаваемость мира — имя,
фамилия, город — это оправдано; для района в тестовом контуре сделка плохая: `Sunote Valley`
и `Fuve Drive` новоделы, зато форма и длина целы, сеть не нужна, прогон повторим по seed.
Нужен район моделью — строка `КЗ-4: model` в конфиге, код не трогается.

**Сквозная замена.** `customer` 403 `MIKE` и `staff` 1 `Mike` — тёзки в разных таблицах: словарь
один на класс значений, а не на колонку, и обе строки получили `MYRON`. Разрывы перечислены
поимённо, с решением на каждый — как два `London` выше. Связи, объём и разнообразие целы,
меряет их машина: 30 числовых критериев, отчёт файлом, тесты раньше кода.

**Обратимость — функция, а не побочный эффект.** Словарь «исходное → замена» шифруется: базу
отдают наружу, результат внешней работы возвращают командой `reverse`. Уничтожить словарь —
закрыть обратный путь.

## Быстрый старт

```bash
git clone https://github.com/SMozg/mysql-pseudonymizer.git
cd mysql-pseudonymizer
pip install -e ".[dev]"

# демо-стенд: данные Sakila лежат в репозитории
cd demo/sakila && cp .env.example .env    # заполнить пароли
docker compose up -d && docker compose ps # дождаться healthy
cd ../..

export SANIT_KEY=...   # ключ словаря, шаблон — .env.example
python -m sanitizer prepare --config config/config.yaml
python -m sanitizer run     --config config/config.yaml --declare base
python -m sanitizer verify  --config config/config.yaml
python -m sanitizer reverse --config config/config.yaml --into sanit_restored
```

`config/config.yaml` — под демо-стенд; для своей базы `config/config.example.yaml` и `fieldmap.yaml`.
`--declare continue` идёт по готовому словарю. Коды возврата: **0** приёмка без провалов ·
**1** красная приёмка · **2** громкая остановка посреди прогона · **3** гейт не пройден.

Тридцатый критерий — повторяемость — красный намеренно: она доказана тестами (два прогона с одним
seed дают побитово совпадающие базы), но в машинную приёмку не выведена — парный прогон не
проброшен в верификатор. Красное с причиной честнее зелёного.

## Пределы

**Требование «замена не должна встречаться среди исходных значений» упирается в размер базы.**
Не гипотеза: прогон дважды встал на классе городов. Городов 599, 42 страны представлены одним —
модель называет уже занятый, потолок повторов исчерпан. Та же арифметика на индексах:
`address.postal_code` — 599 непустых значений против 597 различных в пространстве 10⁵ дают
ожидание случайных совпадений ≈ 3,6, получено 3; порог «не больше одного» неисполним. Лечится
не размером, а замером: проверка переведена с множества значений **на ячейку**, каждая сверяется
со своим исходным. Защита держится на разрыве связи «эта строка ↔ этот человек», а не на
исчезновении слова из базы.

**Страна координаты проверяется прямоугольной рамкой, а не контуром.** `POINT(129.72 33.15) →
POINT(135.94 27.86)` — по рамке Япония, но точка может попасть в море у берегов. Контур вместо
рамки — задача названная, не сделанная.

**Совпадения с чужими значениями остаются и публикуются числом** — 373 на демо-прогоне.
Диагностика, не отказ: `MIKE` у другого клиента о первом не сообщает ничего.

**Модель видит исходные значения** — иначе настоящего города той же страны не получить. Для боевых
ПД — локальная модель или поставщик с договором.

**Проверено на одной базе.** Механизмы общие, классификацию колонок делает человек.

**Это псевдонимизация, а не анонимизация.** Результат обратим, значит по закону остаётся
персональными данными. Кто держит словарь — держит и исходные данные: он шифруется ключом
из окружения и в открытом виде на диск не ложится.

## Что нужно для запуска

Python 3.12 · MySQL 8 со строгим `sql_mode` (`STRICT_TRANS_TABLES`), соединение `utf8mb4` ·
Docker Compose для демо-стенда. Права: чтение исходной схемы, полные права на `sanit_*`,
`SHOW_ROUTINE` и `log_bin_trust_function_creators` при двоичном журнале; root не нужен —
в демо-стенде всё в `demo/sakila/initdb/03-grants.sql`.

Секреты — только через окружение (`SANIT_KEY`, `SANIT_MODEL_KEY`, `SANIT_MODEL_BASE_URL`,
`MYSQL_*`; шаблон — `.env.example`): конфиг уезжает в логи и в git, окружение — нет.
Sakila — образец Oracle под BSD-подобной лицензией.
